Під час роботи з побітовими операціями використовується двійкове подання чисел. Біти традиційно нумеруються починаючи з молодшого, причому наймолодший біт нумерується нулем.  Таким чином біт номер \(i\) відповідає за наявність у двійковому поданні числа степеня, що дорівнює \(2^i\).

Для побітових операцій зазвичай краще використовувати беззнакові цілі типи, наприклад unsigned int, unsigned long long або типи з фіксованою кількістю бітів: uint32_t, uint64_t. Для знакових типів, таких як int або long long, побітові операції також можливі, але з ними є важливі нюанси: подання від’ємних чисел залежить від реалізації, а зсуви можуть призводити до неочевидної або навіть невизначеної поведінки. Тому в прикладах нижче будемо використовувати беззнаковий 32-бітний тип uint32_t (що на більшості платформ збегається з типом unsigned int).

#include <cstdint>

uint32_t x = 50, y = 100;

//у двійковому вигляді x = 0000 0000 0000 0000 0000 0000 0011 0010 = 2^5 + 2^4 + 2^1 = 32 + 16 + 2
//у двійковому вигляді y = 0000 0000 0000 0000 0000 0000 0110 0100 = 2^6 + 2^5 + 2^2 = 64 + 32 + 4

Ми будемо казати, що в числі y=100 встановлені лише три біти: 6-й, 5-й і 2-й (встановлені ті біти, де відповідний розряд у двійковому поданні дорівнює 1). Ми записали 32-бітні числа, доповнивши відсутні розряди спереду нулями, оскільки тип uint32_t має рівно 32 біти.

Наведемо основні побітові операції з цілими числами:

1. Перевірка, чи встановлений i-й біт у числі x?

if (x & (1u << i))
{
    cout <<i <<"-й біт встановлений (дорівнює 1)." << endl;
}
else
{
    cout <<i <<"-й біт скинутий (дорівнює 0)." << endl;
}

Тут використано літерал 1u, тобто беззнакову одиницю типу unsigned int. Це краще, ніж звичайний літерал 1 типу int, оскільки побітові операції та зсуви безпечніше виконувати над беззнаковими значеннями.

Як це працює:

  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число x)
  &
1u << 0 = 0000 0000 0000 0000 0000 0000 0000 0001  (встановлений біт номер 0)
  =       =======================================
  0     = 0000 0000 0000 0000 0000 0000 0000 0000  (нуль, оскільки біт номер 0 у числі x дорівнює 0)

  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число)
  &
1u << 1 = 0000 0000 0000 0000 0000 0000 0000 0010  (встановлений біт номер 1)
  =       =======================================
1u << 1 = 0000 0000 0000 0000 0000 0000 0000 0010  (біт номер 1, оскільки біт номер 1 у числі x дорівнює 1)


  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число x)
  &
1u << 2 = 0000 0000 0000 0000 0000 0000 0000 0100  (встановлений біт номер 2)
  =       =======================================
  0     = 0000 0000 0000 0000 0000 0000 0000 0000  (нуль, оскільки біт номер 2 у числі x дорівнює 0)

---------------------------------------------------------------------------------------------------

  y     = 0000 0000 0000 0000 0000 0000 0110 0100  (число y)
  &
1u << 2 = 0000 0000 0000 0000 0000 0000 0000 0100  (встановлений біт номер 2)
  =       =======================================
1u << 2 = 0000 0000 0000 0000 0000 0000 0000 0100  (біт номер 2, оскільки біт номер 2 у числі y дорівнює 1)

Вираз x & (1u << i) залишає тільки i-й біт у числі. Коли він використовується як логічний вираз в умові оператора if, то ненульове значення (у випадку, коли i-й біт дорівнював 1) позначатиме істинне значення, а нульове (коли i-й біт дорівнював 0) — хибне.

Зазначимо, що якщо Ви хочете використовувати 64-бітний беззнаковий тип uint64_t або unsigned long long, тобто змінна x оголошена, наприклад, як 

uint64_t x;

то необхідно змінити перевірку на 

if (x & (1ULL << i))
{
    cout <<i <<"-й біт встановлений (дорівнює 1)." << endl;
}
else
{
    cout <<i <<"-й біт скинутий (дорівнює 0)." << endl;
}

Знайшли відмінність? Ми використали 1ULL — літерал типу unsigned long long замість літерала 1u типу unsigned int, щоб під час зсуву розряду вліво можна було працювати з бітами 64-бітного числа. Наприклад, вираз 1u << 40 є некоректним для 32-бітного unsigned int, а 1ULL << 40 є коректним, якщо тип unsigned long long має щонайменше 64 біти. Але навіть для 1ULL номер біта має бути меншим за кількість бітів у типі: не можна виконувати 1ULL << 64.

Аналогічні зміни потрібно буде зробити і з усіма наступними прикладами, якщо хочете використовувати 64-бітні числа: замість 1u << i слід писати 1ULL << i, а змінні краще оголошувати як uint64_t або unsigned long long.

Важливо: номер біта i має бути в допустимих межах. Для 32-бітного типу uint32_t можна використовувати номери бітів від 0 до 31, а для 64-бітного типу uint64_t — від 0 до 63. Зсув на величину, що дорівнює або перевищує кількість бітів у типі, є невизначеною поведінкою в C/C++. Наприклад, для 32-бітного типу не можна виконувати 1u << 32, а для 64-бітного — 1ULL << 64.

2. Встановити i-й біт. Це означає зробити i-й біт рівним одиниці. Решта бітів не змінюють свого значення.

x = x | (1u << i);

або коротше 

x |= 1u << i;

 Приклад:

  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число)
  |
1u << 0 = 0000 0000 0000 0000 0000 0000 0000 0001  (встановлений біт номер 0)
          =======================================
          0000 0000 0000 0000 0000 0000 0011 0011  (число x з додатково встановленим бітом номер 0)

  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число)
  |
1u << 1 = 0000 0000 0000 0000 0000 0000 0000 0010  (встановлений біт номер 1)
  =       =======================================
  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (x не змінився, оскільки біт номер 1 у початковому числі і так дорівнював 1)


  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число)
  |
1u << 2 = 0000 0000 0000 0000 0000 0000 0000 0100  (встановлений біт номер 2)
          =======================================
          0000 0000 0000 0000 0000 0000 0011 0110  (число x з додатково встановленим бітом номер 2)

Якщо i-й біт і так був встановлений, то число не змінюється.

3. Скинути i-й біт. Це означає зробити i-й біт рівним нулю. Решта бітів не змінюють свого значення.

x = x & ~(1u << i);

або коротше  

x &= ~(1u << i);
     x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число)
     &
~(1u << 0) = 1111 1111 1111 1111 1111 1111 1111 1110  (встановлені всі біти, крім біта номер 0)
     =       =======================================
     x       0000 0000 0000 0000 0000 0000 0011 0010  (x не змінився, оскільки біт номер 0 у початковому числі і так дорівнював 0)

     x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число)
     &
~(1u << 1) = 1111 1111 1111 1111 1111 1111 1111 1101  
             =======================================
             0000 0000 0000 0000 0000 0000 0011 0000  (скинули біт номер 1 у числі x)

 4. Інвертувати  i-й біт. Тобто якщо i-й біт дорівнював 0, зробити його одиницею, і навпаки, якщо він дорівнював 1, зробити його нулем. Решта бітів не змінюють свого значення.

x = x ^ (1u << i);

або коротше   

x ^= 1u << i;
  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число)
  ^
1u << 0 = 0000 0000 0000 0000 0000 0000 0000 0001  (встановлений біт номер 0)
          =======================================
          0000 0000 0000 0000 0000 0000 0011 0011  (біт номер 0 змінився з 0 на 1)

  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число)
  ^
1u << 1 = 0000 0000 0000 0000 0000 0000 0000 0010  (встановлений біт номер 1)
          =======================================
          0000 0000 0000 0000 0000 0000 0011 0000  (біт номер 1 змінився з 1 на 0)


  x     = 0000 0000 0000 0000 0000 0000 0011 0010  (початкове число)
  ^
1u << 2 = 0000 0000 0000 0000 0000 0000 0000 0100  (встановлений біт номер 2)
          =======================================
          0000 0000 0000 0000 0000 0000 0011 0110  (біт номер 2 змінився з 0 на 1)

Що буде, якщо використовувати знакові типи?

Побітові операції зі знаковими додатними числами часто працюють так, як очікується, але для навчальних і практичних задач краще не покладатися на це без потреби. Особливо обережним треба бути з від’ємними числами та зі зсувами.

Наприклад, якщо змінна має тип int, то вираз 1 << 31 для 32-бітного int намагається встановити знаковий біт. Такий зсув може призвести до невизначеної поведінки, тому краще писати 1u << 31, якщо потрібно отримати маску для 31-го біта 32-бітного беззнакового числа.

Також не можна виконувати зсув на від’ємну величину або на величину, що дорівнює чи перевищує кількість бітів у типі. Наприклад, вирази 1u << 32 для 32-бітного unsigned int і 1ULL << 64 для 64-бітного unsigned long long є некоректними.

Отже, практичне правило таке: для 32-бітних масок використовуйте uint32_t і 1u << i, де 0 <= i < 32; для 64-бітних масок використовуйте uint64_t і 1ULL << i, де 0 <= i < 64.
